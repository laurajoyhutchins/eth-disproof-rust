# Reachable packet-mode states under the literal paper schedule

**Follow-up:** [Global mode-factor support](global-mode-support.md) now proves
that the *admissible weighted factor-table row domain* is also `2^{o(s)}`
under the successful literal paper schedule. Statements below identifying
global support as open describe the earlier, strictly local proof boundary;
they do not invalidate the later weighted-partition argument. Total bit work,
recursively inherited oracle costs and unconditional completion remain open.

**A positive but local theorem.** For every *prepared eager-Python packet
entry* reached during a paper-schedule call that satisfies the declared
packing and precision premises, the number of exponent-vector states held by
that packet's coefficient table is `2^{o(s)}`, where `s` is the Boolean
network size parameter. This neither bounds global factor-elimination states
nor proves that the implementation succeeds on all inputs. In particular it
does **not** establish `2^{o(N)}` in generalized-Sudoku *cells*.

The implementation-to-proof check is `reference/paper_mode_reachability.py`.
Run the finite independent state-enumeration and symbolic schedule tests:

```bash
PYTHONPATH=src:. python -m pytest -q tests/unit/test_paper_mode_reachability.py tests/unit/test_packet_oracle_work_envelope.py
```

## Lemma 1: one processed row can increment at most one exponent

Let `k` target modes have multiplicities `beta_i >= 0`. The actual
`PacketEntry._evaluate_python` initializes its table with key `(0,...,0)`.
For each row it either retains an existing exponent vector (the constant
transition) or increments a single coordinate `i`, conditional on
`alpha_i < beta_i`. Induction on `j`, the number of processed rows, yields

\[
0\le\alpha_i\le\beta_i,\qquad \sum_i\alpha_i\le j.
\]

The number of **possible** keys after `j` rows is therefore bounded by

\[
S_j\le\min\left\{\prod_i(\beta_i+1),\binom{k+j}{j}\right\}
\le(k+1)^j.
\]

The middle term is stars-and-bars, with one slack variable for unused rows.
The last inequality counts `k+1` possible choices per row and permits
collisions. These are combinatorial upper bounds, not exact state counts:
coefficient cancellations or limited row-mode incidence can reduce them.

For row `j` (zero-based), if `c_j` modes contribute at that row, the
implementation performs at most `S_j(1+c_j)` coefficient-table
transitions. Hence its **outer** ring additions and multiplications from
that table update are bounded by

\[
B_{\rm table}\le \sum_{j=0}^{r-1}(1+c_j)
\min\left\{\prod_i(\beta_i+1),\binom{k+j}{j}\right\},
\]

where `r` is the number of rows. The existing packet-work envelope now uses
this sharper bound rather than `r*(1+k)*prod(beta_i+1)`. No production
arithmetic implementation was changed.

An independent enumerator confirms the invariants over randomized small
row-mode incidences. A 12-mode one-row prepared packet has `2^12`
rectangular exponent keys but **13** possible transitions, and its
all-modes coefficient is identically zero. Conversely, `j` independent
rows can produce `2^j` keys: exponential growth in **packet width** is
real, even though this width is sublinear in `s` under the schedule.

## Lemma 2: modes and rows per packet

In the actual `mode_catalog` at a nonzero center `t` with `i=v2(t)`, the
mode constructor visits `y0` in `[0,2^{i+1})`; each `y0` yields at most
`p-1` values of `b`, where `p` is that center's coefficient precision.
For `L=2^a` packet slots, the center loop formally visits `[-L,L)`,
but it calls `mode_catalog` only if `q=h*max(0,u-v2(t)) > 0`. The literal
paper schedule has `a>=2u`; hence every cataloged center satisfies
`i=v2(t)<u<=a/2` and `2^{i+1}<=2^u<=L`. **The negative endpoint
`t=-L` has valuation `a`, and is skipped with `q=0` before the catalog**;
calling `mode_catalog` directly at that out-of-domain center would access
beyond the group-label dimensions. Thus for one packet and one target group

\[
k\le (p-1)L,\qquad r\le L.
\]

This holds even with padded/partly empty packets. In particular the
number of intermediate states in **one packet's table** satisfies

\[
\log_2 S\le L\log_2(1+(p-1)L).
\]

The source tests inspect actual modes generated by a nontrivial packed
network at several precisions. The result does not require an active
astronomical-size paper instance for the underlying structural invariant.

## Lemma 3: the paper schedule makes `L` sublinear in `s`

Put `lambda=(s-1).bit_length()` and inspect the *literal* schedule:

\[
a_d=2\sum_{j=0}^{d}\left\lfloor
\frac{\lambda}{131072\,2^j}\right\rfloor.
\]

For every finite depth, the geometric series yields the strict bound

\[
a_d<\frac{\lambda}{32768},\quad
L_d=2^{a_d}\le 2^{\lfloor(\lambda-1)/32768\rfloor}
=O(s^{1/32768}).
\]

This is a bound on slot width, **not** a claim that a physically
constructible Sudoku board activates the literal schedule. The first
active parameter has `lambda=131072`. The tests check the integer
inequality against the actual schedule without materializing gigantic
rings or networks.

## Lemma 4: conditional precision closure

Assume the paper path's existing child shrinkage invariant
`M_{d+1}<=floor(3*M_d/32)`, input `M_0<=s` and input precision `p_0<=s`.
This includes the direct Sudoku encoding with `s=M` and `p_0=N*t+1`.
For an active call `u_d>=1`, the implementation uses

\[
h_d=\lceil 3M_d/u_d\rceil\le 3M_d,
\]

and a center precision bounded by

\[
p_{d+1}\le p_d+8h_dL_d+8M_d(a_d+1)
\le p_d+32sL_{\max},
\]

because `a_d+1<=2^{a_d}=L_d` at active depths. At most `lambda`
levels are active. Consequently

\[
p_d\le p_0+32\lambda sL_{\max}
=O(s^{1+1/32768}\log s),
\]

which is polynomial in `s`. Substitution into Lemma 2 gives

\[
\log_2 S_d=O(s^{1/32768}\log s)=o(s),
\qquad S_d=2^{o(s)}.
\]

`uniform_paper_packet_bound` computes a conservative integer upper
certificate for *these exact premises*. It rejects `M_0>s` and
`p_0>s`. `paper_packet_state_exponents` checks that symbolic frame
bounds computed by the independent precision-envelope code fit within
it. These executable checks are regressions of the stated inequalities;
**the asymptotic conclusion follows from the mathematical derivation, not
from measuring a finite collection of large integer values**.

## What this does **not** prove

The global mode-elimination engine combines scopes across *many* packets.
One prepared packet with `2^{o(s)}` states does not imply that the number
of combined assignments, intermediate factors, joins, or recursively
generated child evaluations is `2^{o(s)}`. Merely requiring positive
mode weights and per-mode row caps cannot suffice: with `k` independent
unit-weight, binary modes and precision `p>=k+1`, the documented
`weighted_tuples` enumerator admits `2^k` assignments. This is a
synthetic mode-domain witness, **not** a paper-admitted packing family.

Still unresolved:

1. Prove a global, paper-admitted bound on factor scopes, support, joins,
   projected states and total child evaluations, or construct an admitted
   counterexample.
2. Account for cost of preparing entries and modes, recursively inherited
   oracles, integer powers, hashing, exact ring arithmetic and rational
   recovery, including *bit* costs and peak memory.
3. Establish non-refusal on the chosen growing input family, and compose the
   full recurrence.
4. Address the different Sudoku cell parameter `N`: with the current
   direct reduction `s=Theta(N log N)`, a `2^{o(s)}` local lemma alone does
   not imply a `2^{o(N)}` complete algorithm.
