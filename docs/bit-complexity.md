# Bit-complexity boundary and partial recurrence (v0.23.7)

**Status: partial bounds proved; complete worst-case bit complexity and
non-refusal on generalized Sudoku are not proved.** The result is more
informative than a call-count recurrence: it establishes an explicit
counterexample to universal completion, identifies the missing input-size
parameter, and supplies constructive upper bounds for two exact kernels.

This note analyzes the **implemented solver**. It does not assume that a
small-instance equivalence test implies the published algorithm's asymptotic
claims. A refusal is neither a correct Boolean answer nor a running-time
bound for a successful algorithm.

## A real, reproducible counterexample to totality

An empty 4x4 Sudoku (`Puzzle(2, (0,)*16)`) converted using
`non_exponential_sudoku.sudoku.encoding.sudoku_network` has **96 edges**,
**28 vertices** and maximum vertex degree **8**. With the natural
`ContractorConfig(s=28, precision=33, schedule="paper")` and its default
18-edge leaf limit:

- `p=33` is sufficient to represent every 4x4 solution count without
  modular wraparound;
- `lambda = (s-1).bit_length() = 5`;
- `u_0 = floor(lambda / 131072) = 0`;
- the root is terminal and calls `Network.direct`;
- it raises `CapacityError: Direct leaf has 96 edges; limit is 18`.

The reproducer is `test_actual_blank_4x4_sudoku_refuses_literal_paper_leaf`.
It neither estimates a runtime nor calls a separate Sudoku solver. The
**different**, degree-three CNF tensor-graph encoding has 2,880 edges and
2,448 vertices on the same empty puzzle; it is not interchangeable with the
96-edge direct-network ABI. The theorem must specify which reduction it
analyzes.

More generally, for **every** parameter with `lambda < 131072`, `u_0=0`.
The literal paper schedule cannot recurse at its root, independently of how
sparse or dense the given network is. Increasing the leaf limit removes this
particular refusal only by allowing potentially `2^M` exhaustive assignments.
This is a counterexample to *the current implementation's* guaranteed
completion, not a proof that no future exact algorithm can succeed.

## Network size must contain vertex count

Let `M` be edges and `V` vertices including degree-zero vertices. The
network contract states that every edge has one endpoint on each side, so
there are exactly `2M` port incidences. There is no bound of `V` in terms
of `M`: a valid network can have `M=0` and arbitrarily many isolated
vertices. Give each vertex the total, constant-one oracle. The direct
contractor evaluates all `V` oracles even at `M=0`.

**Proposition.** No upper bound on this implementation's bit cost can be a
function of `M` alone for the admitted `Network` type, even assuming
constant-time total oracles. The family above performs at least `V` oracle
calls while `M` is fixed at zero. The test
`test_zero_edge_family_requires_unbounded_oracle_calls` witnesses this.

A recurrence needs at least `(M,V,p,e)` and a bound on each vertex oracle's
cost; it also needs the nested jet and rational-recovery sizes when those
paths are used. If the oracles are arbitrary Python callbacks, no finite
uniform time upper bound exists without a totality and cost hypothesis.

## Quantified direct Sudoku input reduction

For box order `b`, put `n=b^2`, `N=n^2=b^4` cells, and
`t=max(1, ceil(log2 n))` bits per digit. The direct bipartite encoding
(`DirectNetwork.from_puzzle`, subsequently adapted by `sudoku_network`) has
**exact** size formulas:

- `M=3Nt` Boolean edges;
- `V=N+3n` vertices;
- maximum degree `max(n,3)t`;
- `p=Nt+1` precision bits suffice to represent every possible solution
  count without modular wraparound, since the number of grids is at most
  `n^N <= 2^(Nt)`.

Each cell oracle checks three `t`-bit values. Each unit oracle checks `n`
`t`-bit digits for distinctness. A deterministic comparison-based unit
implementation runs in `O(n^2 t)` bit work, and the implemented finite
integer/set test also has a polynomial upper bound. Thus the encoding and
its local oracles have polynomial size and cost in the number of cells.

These exact graph-size formulas are generated by
`reference.bit_work.sudoku_direct_encoding_size` and tested against
construction for box orders 1 through 4. They discharge **the input-size
accounting** for this specific direct encoding. They do **not** establish
that the paper schedule's internal packing hypotheses hold on every
recursive child, or that the solver finishes without capacity refusal.

## Exact direct-leaf operation envelope

Let the input ring be the finite 2-adic extension
`R = (Z/2^p Z)[U]/(f(U))` of degree `e`. Assume every oracle terminates and
returns one well-formed ring element; let `A_v(k,e,p)` bound its bit cost
when called on the vertex's `k` incident bits. The base-case loop makes no
more than:

| Operation | Worst-case count |
|---|---:|
| Binary assignments | `2^M` |
| Vertex-oracle calls | `V * 2^M` |
| Coefficient multiplications | `V * 2^M` |
| Coefficient additions | `2^M` |
| Port-bit reads for oracle arguments | `2M * 2^M` |

These bounds are **attained** (except the edge-case of empty vertices for
port reads) when all oracles return the ring's one element: there is no
short-circuiting. `reference/bit_work.py` calculates the integers, and the
regression tests compare the oracle counts against actual execution. The
counts do not themselves cover oracle internals or the `Padic` constructor.

For an abstract schoolbook implementation of the exact coordinate ring,
`C_add(e,p) = O(ep)` bit operations, and
`C_mul(e,p) = O(e^2(p + log(e+1))^2)` bit operations. The latter follows by
at most `e^2` products of `p`-bit coordinates, `O(e^2)` additions and
monic reduction operations on intermediates of `O(p+log(e+1))` bits. This
is a **constructive arithmetic-algorithm bound**, not a benchmark or an
exact count of Python VM instructions. With
`A = sum_v A_v(deg(v), e, p)`, a conditional bit-operation upper bound for
an exhaustive leaf with a preconstructed `Padic` ring is therefore

\[
 T_{\mathrm{leaf}}(M,V,e,p)
 = O\!\left(M+V+2^M\left[M+V+A+
     V C_{\mathrm{mul}}(e,p)+C_{\mathrm{add}}(e,p)\right]\right).
\]

A separate ring-construction cost must be added when using
`ContractionEngine` from scratch. In particular `modulus_polynomial(e)`
searches for an irreducible binary polynomial instead of receiving a
pre-certified one. It must not be treated as a free setup operation.
This leaf bound does **not** apply to nested `JetRing` values without a
corresponding coefficient-dimension factor.

## Exact interpolation-stage operation envelope

For `n` Newton interpolation points, the implemented
`core.algebra.interpolate` evaluates two prefix polynomials, scales its
basis and multiplies the basis by one linear factor at step `k`. These
polynomials have lengths at most `k+1`. Summing the loop gives the
following **outer** ring-call ceilings:

\[
 N_{\mathrm{mul}} \le 5n(n+1)/2+n,\quad
 N_{\mathrm{add/sub}} \le 5n(n+1)/2+n,\quad
 N_{\mathrm{inv}} = n.
\]

`reference/bit_work.py` reports them, and
`test_interpolation_envelope_covers_actual_ring_calls` checks them against
an instrumented ring. Inversion must be charged separately: the pure-Python
`Padic.inv` obtains an inverse in `GF(2^e)` then performs `O(log p)` Newton
lifts. A constructive (non-tight) schoolbook bound is
`C_inv(e,p) = O(e^3 + (log(p+1)+1) C_mul(e,p))`. Thus the interpolation
stage admits a conditional upper bound

\[
 T_{\mathrm{interp}}(n,e,p)
 = O\big(n^2(C_{\mathrm{mul}}+C_{\mathrm{add}})
          +n C_{\mathrm{inv}}\big).
\]

All `n` sample points must be residue-distinct, so the implementation
refuses when `n > 2^e`; this is a **feasibility condition**, not a theorem
that `n` always fits for every generalized Sudoku reduction.

## A corrected recursive size envelope

For the **paper/interpolate** schedule, let `M_d`, `V_d`, `p_d` be upper
bounds on edge count, vertex count and coefficient precision entering depth
`d`. Let `L_d=2^{a_d}`, `J_d=2L_d-1`,
`h_d=ceil(3M_d/u_d)` and `n_d=M_d J_d+1` for an active call.

- Every created child is checked to have at most
  `M_{d+1} = floor(3M_d/32)` edges. The child retains at most `V_d`
  parent vertices and adds at most `M_d` nonempty packet tensors, because
  every such packet owns at least one distinct parent edge. Hence
  `V_{d+1} <= V_d+M_d`.
- Every center works at precision
  `p_d+8h_d(L_d/2^{v_2(t)})+8M_d(a_d+1)`, so a common upper bound is
  `p_{d+1} <= p_d+8h_d L_d+8M_d(a_d+1)`.
- It requests at most `J_d` nonzero centers, each at most `n_d`
  deformation evaluations. Each deformation starts at most
  `B_d = max_child_contractions` recursive children using elimination,
  or `B_d = 64*max_tuples` using enumeration.

These inequalities are **one-sided**, because early leaf selection,
capacity refusal and zero factors may make a branch shorter. The pure
`reference/precision_envelope.py` propagates them without allocating
astronomical rings. Its call-count unfolding agrees with the prior
independent `reference/recurrence_calls.py` model. Every canonical Padic
coordinate vector on such a path occupies at most `e * max(p_d)` payload
bits, but this does **not** bound intermediate `Fraction` numerator and
denominator sizes in recovery, `JetRing` values, Python object overhead,
or arbitrary oracle state.

Let `U_d(M_d,V_d,p_d,...)` be an actually **proved** uniform bound on the
local *non-recursive* bit operations, including packing, mode cataloguing,
factor elimination, packet entries, interpolation, exact Hermite rational
recovery, integer allocations, and all vertex oracles. Only *if* such a
bound exists, then the recurrence satisfies

\[
 T_d \le U_d + (J_d n_d B_d)T_{d+1},
 \quad
 T_0 \le \sum_{d=0}^{D}
 \left(\prod_{j<d}J_j n_j B_j\right) U_d,
\]

with the obvious terminal convention for `J_d n_d B_d` and a matching
terminal `U_D`. This is a **conditional decomposition**, *not* a
completed worst-case bit-complexity proof. The existing recursive-call
bound proves only the branching term; the complete `U_d` is unknown.

## Outstanding theorems, not implementation tasks

1. Fix the growing Sudoku family and which of the two available
   reductions the theorem analyzes. The direct encoding now has exact
   `M(N)`, `V(N)`, degree and precision formulas, and polynomial-time
   local oracles, but the theorem-specific hypotheses and `s(N)` choice
   must be checked through every recursive child. The two encodings are
   different and cannot silently share a complexity statement.
2. Prove either that the configured resource limits admit every instance in
   that family, or replace capacity refusal with a mathematically justified
   total branch. The concrete 4x4 refusal shows this is presently false.
3. Bound *all* nonrecursive work, including factorization, mode-state
   enumeration, packet preparation, `Fraction` growth, any nested jets, and
   modulus construction. Bound peak retained bit memory as well.
4. Solve the resulting bit recurrence using those proved bounds and show
   whether its exponent is `o(N)`. Neither local arithmetic speedups nor
   small-parameter timings establish this asymptotic statement.
5. Independently verify correctness and the non-refusal guarantee of the
   resulting algorithm. A `CapacityError` must never be counted as a solved
   Sudoku instance.

The current result is a *negative theorem plus quantified input-size and
partial positive cost lemmas*, supported by executable witnesses. That is genuine progress:
we now know exactly where the proposed worst-case claim fails and which
mathematical obligations a subsequent algorithm must discharge.
