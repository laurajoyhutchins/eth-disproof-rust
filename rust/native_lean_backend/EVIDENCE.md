# G1 independent evidence and release ledger

This document tracks checklist [#193, items 31–40](https://github.com/laurajoyhutchins/eth-disproof-rust/issues/193) for the **in-process Lean 4.34.1 → Rust executable-IR compiler**. It does not claim completion of the general-purpose compiler (G1) or of the source-defined ETH program (G2).

## Reproduce at a checked-out, exact revision

Prerequisites: Linux x86-64; the exact Lean 4.34.1 compiler/headers at commit `5045d0056413266e57c625dcd7c365b10e377c52`; Rust/Cargo 1.99.1; a C compiler; `ar`; and the existing pinned dependency/ABI checks in `build.rs`.

```sh
cd rust/native_lean_backend
export LEAN_PREFIX=/absolute/path/to/pinned/lean-4.34.1
lake build
bash scripts/check.sh
bash scripts/check-evidence.sh
# Optional performance observation, NOT a backend speedup comparison:
bash scripts/bench-evidence.sh
```

The normal public API remains `#native_rust Name as "export" to "file.rs"` (single executable declaration) and `#native_rust_closure Name as "export" to "file.rs"` (direct-call closure through imported executable IR). Both require loading the built native shared library into the same Lean process with `--load-dynlib`. `scripts/check.sh` provides the reproducible invocation and configures environment paths. This is **not yet** a one-command general-purpose installation or a multi-root Cargo emitter; see #193 G1-A.

### Deterministic property differential suite

`examples/PropertyDef.lean` defines a bounded-depth, scalar recurrence with unsigned wrapping, conditional branches, and recursive calls. It is compiled as an ordinary imported Lean declaration. `examples/Property.lean` directs the native compiler to emit the standalone Rust implementation and **independently asks Lean to evaluate** the original declaration for 128 fixed seeds and eight deterministic shrink candidates per seed.

`examples/property_driver.rs` runs the generated Rust against all 1,024 Lean-produced outputs. On mismatch, it prints the seed, input, fuel, original Lean output, generated Rust output, shrink stage, and a one-seed reproduction command; it chooses the smallest failing candidate in the precomputed ladder. This is **bounded, precomputed shrinkage**, not a claim of globally minimal counterexamples or of full QuickCheck-style generation.

The test seed sequence is generated by a fixed-width 64-bit LCG starting at `0x9E3779B97F4A7C15`. Boundary inputs include 0, 1, 2, 3, 7, 42, `2^32-1`, `2^32`, `2^63`, `2^64-1`. Oracle values are computed by Lean, not copied from or reconstructed by the Rust backend.

The suite also compiles the emitted code as a **new standalone Cargo executable** with no Lean runtime dependency, runs its test binary, and checks `cargo test --offline` and `cargo clippy --offline --all-targets -- -D warnings`. The existing `scripts/check.sh` separately exercises ABI, 1,984 fixed/seeded Lean/Rust assertions, refusal preservation, deterministic closure, and backend unit tests. Neither fixture replaces testing on independent Lean projects.

### Performance evidence policy

`scripts/bench-evidence.sh` is **opt-in** and writes three raw, repeated *fresh-process* measurements of:

- Lean invocation time and peak RSS, **including** elaboration, in-process Rust codegen, and generation of the independent test vectors (not pure FFI overhead).
- Generated Rust `rustc -O` build time and peak RSS.
- Generated executable wall time, peak RSS, source/binary bytes, generated output identity.

Results are under `artifacts/bench-native/`. Repeated calls are **not** cold-cache vs warm-cache measurements. No source-to-Rust speedup should be claimed from this suite: no semantically equivalent Lean native C runtime and legacy JSON/source-graph baseline has yet been measured.

For #193 item 36, extend this harness only after constructing a **shared supported program with identical inputs, outputs, and algorithm** across all three backends. Then measure source hash, toolchain, cold/warm definitions, process startup, compilation, intermediate bytes, execution, RSS, and refusal rates separately. If any backend cannot compile that common program, record **unsupported**, not an invented runtime comparison.

## Imported standard-library probes (not three external projects)

The exact pinned original Lean 4.34.1 source is exercised without hand-copying or rewriting implementations. `examples/ProbeNatGcd.lean`, `ProbeListReverse.lean`, and `ProbeStringIntercalate.lean` independently check real original Lean behavior, then attempt native in-process extraction. All three **explicitly refuse** unsupported compiled IR in [native CI 43507863090](https://github.com/laurajoyhutchins/eth-disproof-rust/actions/runs/43507863090), commit `714524c06e8ee2b47a74957722abf052f9831e72`. Their original behavior is valid, but generated Rust does **not** exist. Precise refusals, prior-output preservation, and peak RSS/time are saved in `artifacts/imported-probes/`. This provides a reproducible negative coverage baseline. It **does not** satisfy checklist item 32's requirement for three nontrivial independent projects actually building and running.

## Atomic bundle publication and build receipts

`scripts/compile-bundle.sh` is a reproducible build wrapper around the existing in-process Lean compiler. It does not replace its backend or introduce serialized JSON IR. A successful invocation accepts an imported module, actual root, source file, new destination directory, and optional Rust export name:

```sh
cd rust/native_lean_backend
# First build the backend using the pinned toolchain and scripts/check.sh.
mkdir -p artifacts/bundles
bash scripts/compile-bundle.sh PropertyDef Property.hop \
  examples/PropertyDef.lean artifacts/bundles/property-hop property_hop
```

The script stages the module's original source, Lean `.olean`, a temporary command, generated Rust source, a strict `rustc -D warnings` standalone Rust library, and `closure.txt` extracted from generated IR declarations. It records the exact source/revision/toolchain, original source SHA-256, compiled module SHA-256, native ABI and backend SHA-256, native plugin SHA-256, declaration-closure hash, generated Rust hash, and emitted library hash in `receipt.txt`, then **publishes the entire directory as one atomic rename**. Existing destinations and invalid roots/output paths refuse. Failed or unsupported compilation leaves no published partial directory. `scripts/check-bundle.sh` verifies both success and negative cases on pinned CI.

A receipt with `status=GENERATED_COMPILED_UNVERIFIED` means **only** that the generated standalone Rust library compiled cleanly. It is not a semantic conformance report. The original module source and generated closure are included, but transitively imported modules are **not yet exhaustively hashed**. Direct use of the low-level `#native_rust`/ `#native_rust_closure` commands does not automatically produce such a bundle; consequently checklist #39 still remains open until this becomes the standard interface and all successful builds carry the specified complete evidence.

### Claim boundary

**Tested, once CI is green:** the pinned Lean compiler object passes in process to the Rust backend, and the supported scalar/Boolean/direct-recursive subset produces matching outputs on the enumerated finite fixtures. Negative refusals and independent emitted-Cargo build are also tested.

**Not proved:** a general semantic-preservation theorem, all reachable Lean IR/runtime semantics, absence of memory errors across arbitrary inputs, full transitive coverage, a standalone ETH program, source-defined noncomputable residualization, physical trace parity, or asymptotic resource bounds. Unreachable/unsupported IR remains a precise refusal obligation, not an implicit host implementation.

## Troubleshooting and refusal policy

- `Expected Lean 4.34.1` or ABI mismatch: install the **source-pinned** release and headers, not a nearby Lean version. Do not bypass `build.rs` checks.
- Missing `LEAN_PREFIX`, shared library, or `NativeRust.olean`: run the documented baseline `check.sh` after `lake build`. Its environment variables are process-local.
- Unsupported primitive, `sorryAx` dependency, missing imported IR, invalid output identifier, or unsupported runtime value: treat the failure as **unsupported source**, not a compiler success. The codegen command must refuse the whole closure and preserve the previous output.
- Property mismatch: run `examples/property-test --seed N`; preserve the emitted Rust, `PropertyDef.lean`, seed/stage and complete receipt before reducing the case.
- Cargo/Clippy failures in generated Rust: this is a compiler defect within the supported subset, not a reason to disable strict validation.
- Out-of-scope data types and noncomputable ETH declarations: do not substitute a rewritten algorithm or an exponential fallback.

The CI receipt is **evidence of a run at a commit**, not a mathematical proof. Mark a G1 item complete only after an accepted source change and a successful exact-head report, or a reviewed documentary-only contract.
